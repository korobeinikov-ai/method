# База

Опыт автора: что делать и где он обжигался. Это направление, детали решай сам по документации Supabase.

База — большая Google-таблица в интернете. Заводи её, только когда данные должны пережить новую выкладку. От человека
нужны только руки: регистрация на https://supabase.com/dashboard. Цены сверь на https://supabase.com/pricing.

## Ключи и права
- Строка подключения — это ключ: мимо чата, как в навыке `railway`, через `klyuch.py`. Файлы с ключами не ищи по имени
  настройки: поиск печатает всю строку, и пароль попадает в разговор.
- Пароль базы — только буквы и цифры: спецзнак ломает инструмент миграций.
- Каждой части свой пользователь с минимальными правами. Главный пароль у всех — это одна утечка на всю базу и одна
  замена, которая задевает всё сразу. Разовым скриптам тоже свой пользователь, без прав на устройство базы.
- Новая таблица рождается закрытой, доступ выдаётся явно. Ключа базы в браузере быть не должно.
- Замена пароля: новый проверить, разложить по частям, выложить их заново, старый отозвать последним. Не в час пик.
- Запись в настоящую базу из разговора — только по явному «да» человека.

## Соединения
- Лимит соединений общий на проект: считай сумму всех частей, вместе со сборкой, выкладкой и запуском на компьютере. Сверх
  лимита соединение рвётся с ошибкой про SSL, а не про лимит. Размер пула ставь по реальной нагрузке.
- Постоянные части — через сеансовый порт, разовые скрипты — только через транзакционный: иначе скрипт займёт линии
  живой части, и человек получит отказ.
- На транзакционном порту соединения общие. Настройка сеанса (`SET` без `LOCAL`, смена роли, «только чтение», схема поиска)
  прилипает и достаётся чужой части: внезапное «нет прав» или запись запрещена. Только `SET LOCAL` внутри транзакции.
  Перед запуском старых скриптов проверяй их на это. Права проверяй без смены роли.
- Замки только транзакционные. Сеансовый замок и его снятие уходят на разные соединения: снятие молча не срабатывает, и
  сбой мигает.
- Таймаут запроса задавай настройкой роли в базе и проверь через `SHOW`: параметр из программы через пулер не применяется.
- В начале скрипта проверь, что он смотрит в нужную базу: настройка может указывать на старую копию.

## Транзакции
- В транзакции нет сети: прочитал, закрыл, сходил наружу, записал итог короткой транзакцией.
- Под замком только «проверил и записал», всё остальное после `COMMIT`. Ставь `lock_timeout`.
- Транзакцией владеет один верхний слой: вложенный `COMMIT` отпускает замок раньше времени.
- Шаги, которые обязаны совпасть (оплата и статус), — одна транзакция: иначе человек видит «успех», а данные разошлись.
- Фоновую работу запускай после `COMMIT` и передавай ей простые данные: до него она видит старое.
- У внешнего вызова есть таймаут и понятная судьба отказа. Один молчаливый сбой оставляет запись «обработанной» навсегда.

## Миграции
- Устройство базы меняй только миграцией из репозитория: созданное руками, вместе с триггерами, потеряется и забудется.
- После выкладки докажи применение: версия в базе и строка в журнале. Инструмент может всё откатывать без ошибки.
- Сбой миграции должен останавливать выкладку, а старая версия — работать дальше. Без проверки здоровья миграция на старте
  кладёт часть целиком.
- Порядок выкладки решай заранее: кто упадёт, если другой приедет раньше. Он бывает разным.
- Прогони миграцию на временной базе вверх, вниз, вверх. После неё обнови снимок схемы в репозитории: тип колонки
  смотри в нём, а не угадывай по имени.
- Ограничение в базе должно совпадать с настоящим правилом дела: слишком грубое мешает разрешённому действию.

## Бэкап и восстановление
- Три слоя: откат на минуту, снимки Supabase, свой дамп вне Supabase. Снимки умирают вместе с аккаунтом, снимок суток
  теряет день. Откат на минуту платный, и общий потолок трат его не держит: сверь цену и спроси человека.
- Бэкап настоящий, только если его развернули в чистую базу и сверили таблицы, индексы, политики и строки. Без
  заранее созданных ролей политики доступа молча не создаются.
- Свой дамп: снимай через сеансовый порт, пиши во временный файл, подозрительно маленький не засчитывай. При сбое —
  тревога, после успеха — стук во внешний пульс: незапущенную задачу изнутри не поймать.
- На экране отката сверь подпись часового пояса с настоящим временем: она могла устареть, а час при откате дорог.

## Время
- Способ перевода времени выбирай по типу колонки из схемы: на колонке без зоны он врёт, и строки уезжают в другой день.
- Одна функция времени на проект, новые таблицы только с зоной. Ручные поправки на часы расходятся между частями.

## Рассылки, повторы и дубли
- Сначала пометка, потом отправка: атомарная вставка с уникальным ключом или обновление только пустой метки. Иначе
  перезапуск шлёт дубль. Задача рассчитана на один экземпляр: перед вторым проверь её.
- Три исхода отправки различай явно: сервер отказал; отказ до запроса (метку снимай); неизвестно. Таймаут и обрыв —
  «доставка неизвестна»: метку не снимай и не шли повторно. Потерять одно дешевле, чем задублировать.
- Сбой при снятии метки повторяй и сообщай громко, иначе запись навсегда считается обработанной.
- Сам повторяй только временные ошибки и случаи, когда соединение не выдали.
- Успех — только явное подтверждение: пустой ответ 200 успехом не считай. Неизвестный исход не показывай человеку кнопкой
  «отправить»: он задублирует сам.
- «Принято отправщиком» — не доставка: ноль ошибок в журнале не значит, что всё дошло.
- Входящее событие, не легшее в базу, повторяй сам: внешний сервис его не дошлёт. Сохранение делай безопасным для
  повтора, после лимита попыток шли тревогу.

## Проверка и наблюдение
- Каждая фоновая задача пишет в журнал запусков в базе, изнутри своего `try/catch`: снаружи ошибку съест `catch`, а журналы
  Railway обрываются на выкладке.
- Нужен внешний сторож: внутренние падают вместе с частью, и этого никто не видит.
- Проверка здоровья ходит настоящим путём. Пустой ответ и тишина — сбой.
- Гонки и откаты проверяй на локальной базе: тест не стартует на нелокальном адресе, шаг ломай намеренно. Модуль,
  подключающийся при импорте, иначе полезет в настоящую базу.
- Разовое чтение настоящей базы — транзакция `READ ONLY` с `ROLLBACK`: следов не остаётся.
- Пробные строки убирай строго по уникальному ключу, а не по похожему значению: снесёшь настоящую запись.

## Устройство данных
- Одна дверь на запись важной сущности и один словарь статусов: новый путь записи тихо пропускает побочный шаг.
- Индекс строй под запрос: сначала равенство, потом диапазон. Постоянное условие выноси в частичный индекс.
- Таблице-журналу сразу задай срок чистки, цену опроса по таймеру считай заранее: сырой журнал съедает базу.
- Исходное значение при смене статуса не затирай: его уже не восстановить.
- Большие числа и суммы сравнивай по значению: библиотека отдаёт их то числом, то строкой.
