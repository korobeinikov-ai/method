# Railway

Railway — компьютер в интернете, который не выключается. Эта часть общая: бот, сайт и задачи по расписанию
идут по одним шагам, разница в перезапуске (шаг 4). Всё техническое делай сам, человеку — только руки: прямая
ссылка и что нажать. Команды Railway запускай из корня проекта: связь с Railway запомнена по папке.

**Главное правило:** выкладываем только то, что сохранено на GitHub. Ручная выкладка из папки берёт
несохранённое, а следующая автоматическая откатит рабочий код. Поэтому `railway up` не используем.

## 1. Подготовка
1. Запусти `bash "${CLAUDE_SKILL_DIR}/../start/instrumenty.sh" railway`. Программа ставится в `~/.local/bin`;
   не находится по имени — добавь эту папку в `PATH` команды.
2. Нужна закрытая копия проекта на GitHub: Railway берёт код оттуда. Нет аккаунта — https://github.com/signup.
   Копии нет — заведи её, как в шаге «За дело» проводника.

## 2. Честно про деньги — до регистрации
Сверь цены на https://railway.com/pricing, они меняются. Скажи человеку одним сообщением:
- **Пробный период:** $5 один раз, до 30 дней, карта не нужна. Хватает, чтобы увидеть результат.
- **Free:** потом $1 в месяц, не копится. Для круглосуточной работы запаса почти нет.
- **Hobby:** $5 в месяц, работа сервисов на эти $5 уже включена. Вышел расход за $5 — платится весь расход. Это
  честная цена постоянной работы.
- На пробном и Free перезапуск ограничен 10 попытками: после них выложенное лежит молча, пока кто-то не заметит.

Первый запуск — на пробном. До того как на бота начнут полагаться люди, предложи Hobby:
https://railway.com/workspace/plans. Если Railway ограничил сеть из-за нового аккаунта GitHub, Hobby это снимает.

## 3. Вход и связь с GitHub (руки человека)
1. Вход делает сам человек: «Наберите `! railway login` и нажмите Enter. В браузере нажмите вход через GitHub и
   подтвердите». Вход через GitHub делает его главным ключом от всего: после запуска посоветуй включить там
   двухфакторный вход: https://github.com/settings/security. Проверь `railway whoami`.
2. Открой https://github.com/apps/railway-app/installations/new. Человеку: «Выберите свой аккаунт, затем Only
   select repositories, отметьте копию проекта и нажмите Install».

Ключ Railway в проекте не заводим и в `.env` не кладём: протухший ключ из файла перебивает рабочий вход.

## 4. Выложить
Сначала спроси человека, называя всё прямо: «Создаю на Railway проект <имя>, выкладываю в него <часть> и передаю
туда её ключи. Да?». Охрана пропускает выкладку только с таким согласием. Остановила — скажи, что именно, и
попроси подтвердить словами или набрать эту команду самому через `!`. В обход не иди.

Часть — папка внутри проекта. Сначала `railway status`: папка уже связана с проектом — `railway init` пропусти, иначе
он заведёт новый проект. Подставь имя части вместо `bot`:

```bash
railway init --name <проект>
railway add --service bot
railway environment edit --service-config bot source.rootDirectory bot
railway environment edit --service-config bot deploy.startCommand "python main.py"
python3 "${CLAUDE_SKILL_DIR}/klyuch.py" peredat ИМЯ_КЛЮЧА --service bot --bez-vykladki
railway service source connect --repo <логин/репо> --branch main --service bot
```

Файлы настроек `railway.json` и `railway.toml` в новых проектах не работают: настройки задаём этими командами.
Команду старта задавай явно: автоопределению не доверяем. Часть, которая работает постоянно, на Hobby перезапускай
всегда: `railway environment edit --service-config bot deploy.restartPolicyType ALWAYS`. Задаче, которая отработала
и завершилась, ставь `NEVER`, иначе она будет запускаться снова и снова.
Потом сверь на месте, что настройки легли: `python3 "${CLAUDE_SKILL_DIR}/klyuch.py" nastroyki`. Часть настроек молча не подхватывается.

**Потолок трат.** Поставь `railway usage limit set --target workspace --soft 7 --hard 10`. $10 — минимальный потолок,
при нём всё на аккаунте выключается, а при $7 приходит письмо. Скажи об этом человеку. На аккаунте уже что-то
работает — сначала спроси: потолок общий на весь аккаунт.

## 5. Проверить, что выложилось
«Сохранил» не значит «выложилось». После каждой выкладки:
1. `railway deployment list --service bot --json`: появилась новая выкладка, она от нужного сохранения и
   дошла до статуса `SUCCESS`. Новой нет — смотри `POLOMKI.md`.
2. Сначала `python3 "${CLAUDE_SKILL_DIR}/klyuch.py" zhurnal --service bot`: в журнале не должно быть значений ключей.
   Только потом смотри сам журнал: `railway logs --latest --service bot --lines 100`. Часть запустилась, ошибок нет.
3. Проверь делом: то, что видит человек, должно работать. Для бота — настоящее сообщение в Telegram.
4. Через минуту посмотри журнал ещё раз: `SUCCESS` не значит, что часть жива, а журнал отстаёт.
5. После самой первой выкладки сохрани мелкую правку кода и убедись, что появилась новая выкладка. Первую запускает
   подключение, а не сохранение: связь может стоять, а сохранения выкладку не создавать. Нет новой — смотри `POLOMKI.md`.

## 6. Видеть ошибки и чинить
- Журнал в разговор — только после `klyuch.py zhurnal --service bot`. Журнал работы: `railway logs --latest --service bot --lines 200`.
  Журнал сборки: `railway logs --build --latest --service bot --lines 200`. Без `--latest` Railway показывает прошлую удачную
  выкладку, а не новую.
- Настройки смотри только именами: `python3 "${CLAUDE_SKILL_DIR}/klyuch.py" imena --service bot`.
  ⛔ `railway variable list` и `railway environment config` печатают значения ключей — в разговор их не выводи.
- Railway помечает как ошибку всё, что программа пишет в поток ошибок. Важность смотри по самой строке.
- Сломалось — сначала причина, навык систематической отладки. Типовые случаи — в `POLOMKI.md`, прочитай его.

## 7. Новая настройка или ключ
- Новый ключ: человек копирует его, ты запускаешь `klyuch.py vzyat ИМЯ` и `klyuch.py peredat ИМЯ --service bot`.
  Он заработает только с новой выкладкой: `peredat` запускает её сам. Изменение в панели Railway надо ещё подтвердить кнопкой Deploy.
  Удаление настройки выкладку не запускает: после него `railway redeploy --service bot --from-source -y`.
- Файлы вне хранилища при новой выкладке пропадают. Данные, которые надо хранить, — в базу, и только когда задаче надо.
- Запиши в карте части: где живёт, какие настройки нужны. Значения — никогда.
